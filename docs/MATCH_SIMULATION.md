# Симуляция матча (Dynasty.MatchSimulation)

Описывает **реализованное** состояние (этап 01). Спека: §5, §31.

## Сборка матча
`Match.Create(RulesetContent ruleset, ulong seed)` → `SimulationKernel<MatchState>`:
1. Валидирует ruleset и получает `RulesetDescriptor` (ID, версия, SHA-256). Невалидный ruleset → `InvalidOperationException`.
2. Тик-рейт берётся из ruleset'а (базовый: 30 тиков/с).
3. Строения ставятся из `Map.Structures` до первого тика.
4. Системы регистрируются в порядке, приведённом ниже.

## Порядок систем в тике
| # | Система | Что делает |
|---|---|---|
| 1 | `WaveSpawnSystem` | По расписанию ruleset'а спавнит волну на каждой линии для обеих команд (Dawn — с начала линии, Dusk — с конца) |
| 2 | `TargetingSystem` | Сохраняет валидную цель или берёт ближайшую атакуемую (по расстоянию между краями, при равенстве — меньший ID). Крипы ищут в радиусе обнаружения, башни — в радиусе атаки и бьют только юнитов |
| 3 | `MovementSystem` | Крип с целью идёт к ней до радиуса атаки; без цели идёт по линии; после конца линии — к ближайшему уязвимому вражескому строению |
| 4 | `AttackSystem` | Начинает атаку (`AttackStarted`), через attack point наносит урон (`DamageDealt`). Урон = бросок в [min, max] × множитель брони |
| 5 | `CleanupSystem` | Удаляет погибших (`UnitKilled` / `StructureDestroyed`); падение древнего → `MatchFinished`, победа противника, конец симуляции |

## Правила
- **Дистанции** — между краями: расстояние между центрами минус оба радиуса. Одно и то же условие (`Geometry.WithinEdgeRange`, через квадраты) используется и для движения, и для атаки.
- **Броня:** множитель = 1 − f·a / (1 + f·|a|), f из ruleset'а (базовый 0.06). Отрицательная броня усиливает урон.
- **Одновременные удары:** атака, у которой момент удара выпал на этот тик, наносит урон, даже если атакующий погиб раньше в этом же тике. Иначе порядок обработки давал бы преимущество одной из сторон.
- **Неуязвимость строений:** `ProtectedBy` + `VulnerabilityRule` (`AnyProtectorDestroyed` — базовые башни после падения любой T3; `AllProtectorsDestroyed` — древний после обеих T4). Неуязвимое строение нельзя ни выбрать целью, ни ранить.
- **Победа** определяется только реальным разрушением древнего.

## События (schema v1)
`match.creep_spawned`, `match.attack_started`, `match.damage_dealt`, `match.unit_killed`, `match.structure_destroyed`, `match.finished`.

## Базовые правила `dynasty.base@1`
Карта 10000×10000, точечная симметрия относительно центра (проверено тестом). Линии top/mid/bot; на каждой T1–T3; база: две T4 и древний. Волна каждые 30 с: 3 melee + 1 ranged. Все числа оригинальные.

Лабораторный вариант `dynasty.lab.dawn-siege@1`: у Dawn в волне ещё 2 осадных крипа. Нужен, чтобы проверить полный путь до победы через настоящие бои.

## Наблюдения (Match Lab, 2026-10-24)
- Лабораторный матч: Dawn побеждает примерно за 3:40–3:50 (seed 1–3), порядок разрушения корректный.
- Базовый матч: за 30 минут башни падают с обеих сторон, победителя нет. Потери крипов Dawn/Dusk на 20 seed: Dusk теряет больше в 10 случаях из 20, средняя разница +0,4 — систематического перекоса нет.
- Скорость headless: около 50–90 тыс. тиков/с (Release), 30-минутный матч считается примерно за 0,6 с.

## Ограничения (сознательно отложено)
- Нет столкновений и раздвигания юнитов; крипы могут стоять в одной точке.
- Нет графа проходимости и поиска пути: крипы ходят только по вейпоинтам линии. Нужно героям, этап 02/03.
- Снаряды мгновенные: урон в момент attack point, без времени полёта.
- Нет бараков и супер-крипов, золота и опыта (некому получать до героев), приоритетов башен (агр на героев).
- Нет рельефа, высот и обзора (этап 03).
- Юниты обновляются в тике последовательно. Измеримого перекоса нет (см. выше), но это стоит перепроверять при каждом новом механизме.
